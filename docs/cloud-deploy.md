# Выкладка на Vercel и Supabase

Пилот на уже занятых мощностях. Отдельный кластер не поднимается. Одновременно хватает 3–4 соединений.

Решение 20.11.2026: на сервере пока нет персональных данных семьи и нет заметной нагрузки, поэтому общий стол едет в существующий проект Supabase, а сайт и API — на Vercel. Личный слой подростка (чек-ины, журнал, блоки, баллы карты, «Моё», аватар) по-прежнему остаётся на устройстве. Когда на сервере появятся данные реальной семьи, серверный слой возвращается в российское облако: [cloud-deploy-ru.md](cloud-deploy-ru.md), 152-ФЗ.

## Что общее и что своё

Тот же приём, что у Career Evidence OS: один проект Supabase, у каждого приложения своя схема. Там уже есть `career_os` и таблицы другого приложения в `public`. Для этого приложения схема `adolesson`. Её создаёт сам API при первом запуске.

| | Общее | Своё у adolesson |
|---|---|---|
| База | Проект Supabase, регион `eu-west-3` | Схема `adolesson`. В `public` и `career_os` таблицы не пишутся |
| Вход | У соседних приложений — Supabase Auth | Логин и секрет участника семьи, cookie `session`. Учётки Supabase Auth это приложение не использует |
| Сайт | Аккаунт Vercel, регион `fra1` рядом с базой | Один проект: статический `frontend/` и API с одного адреса |

Браузер не получает anon-ключ Supabase. К Data API эта схема не подключается: в настройках проекта её нет в списке Exposed schemas.

Пул соединений — session, порт `5432`. Порт `6543` (transaction) рассчитан на другой режим: он не держит транзакцию API. На 3–4 человек session pooler как раз по размеру. У каждой копии функции на Vercel в пуле одно соединение.

## Переменные

Секреты — только в Vercel → Settings → Environment Variables. В репозиторий их не кладут.

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Session pooler из Supabase → Connect. Хост `aws-0-eu-west-3.pooler.supabase.com`, порт `5432`, пользователь `postgres.<project-ref>`, база `postgres` |
| `SUPABASE_REGION` | `eu-west-3`. Нужна, только если в `DATABASE_URL` ещё прямой хост `db.<project-ref>.supabase.co` |
| `COOKIE_SECURE` | `1` |
| `CORS_ORIGIN` | Не задавать. Фронт и API на одном адресе Vercel, cookie `SameSite=Lax` |
| `VITE_API_URL` | Не задавать. Сборка ходит в `/api` того же сайта |
| `DB_SCHEMA` | Не задавать. На хосте Supabase схема `adolesson` подставляется сама |

Прямой хост `db.*.supabase.co` с Vercel часто не открывается. Строка с портом `6543` или с `sslmode=require` тоже подойдёт: процесс перепишет её на session pooler и включит TLS без проверки чужого сертификата. Так уже сделано в соседнем проекте: `sslmode=require` в URL текущий `pg` трактует как проверку цепочки и обрывает соединение.

Локальный `postgres://adolesson:adolesson@localhost:5432/adolesson` эта переписка не затрагивает. Схема `adolesson` локально не создаётся.

## Проект на Vercel

Корень репозитория — один проект Vercel с двумя сервисами, [vercel.json](../vercel.json). Регион — `fra1`. Прототип в этот проект не входит, его публикует GitHub Pages.

- `frontend` — публичный сайт, все пути кроме `/api`. Привязка к `backend` кладёт внутренний адрес в `BACKEND_URL`. Эту переменную задаёт Vercel, в настройках проекта её не пишут. Её читает сервер разработки (`vercel dev`). В браузерную сборку она не входит.
- `backend` — публичный API на `/api/*`. Браузер ходит на этот путь того же адреса, поэтому cookie `session` остаётся на сайте.

Контракт `docs/api/openapi.yaml` при сборке копируется в корень сервиса `backend`: у сервиса свой каталог, и файл контракта лежит на уровень выше. `npm run dev` и тесты читают исходный файл из `docs/`.

1. Vercel → Add New → Project → этот репозиторий. Root Directory оставить корнем, не `frontend/`.
2. Вписать переменные из таблицы. `COOKIE_SECURE=1` обязателен: Vercel принимает HTTPS, а функция видит HTTP за прокси. Без флага браузер не сохранит сессию.
3. Deploy.
4. `curl https://<проект>.vercel.app/api/health` → `{"status":"ok"}`. Первый вызов применяет миграции в схему `adolesson`.
5. Открыть тот же адрес, создать семью на `#/parent/table`. После обновления страницы `GET /api/session` возвращает её. Подросток входит по `#/join/{token}` с другого устройства.
6. В SQL Editor проекта: таблицы лежат в `adolesson`, не в `public` и не в `career_os`. Чек-инов, журнала и баллов там нет.

GitHub Pages по-прежнему публикует прототип `prototype/dist`, не этот фронт.

Образ `make api-image` для этой выкладки не нужен.

## Что не смешивать

- Не добавлять `adolesson` в Exposed schemas и не выдавать anon-ключ фронту.
- Не хранить в этой базе имена и записи реальной семьи, пока сервер снова не стоит в РФ.
- Не поднимать вторую базу ради пилота: схемы уже разделяют приложения на одном проекте.
